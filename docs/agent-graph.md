# Agent Graph

## What Is the Agent Graph

The agent graph is a structured knowledge representation of the XPoster codebase,
generated automatically by [`graphify-dotnet`](https://github.com/elbruno/graphify-dotnet)
and persisted to `docs/agent-graph/` on every merge to `develop`.

It maps relationships between source code, documentation, and infrastructure nodes,
enabling AI coding assistants (GitHub Copilot, Cursor, Claude, etc.) to navigate
the codebase with full context — without reading every source file.

> This is a **developer tooling** artifact. It has no relation to the AI agents
> described in the Phase 4 roadmap, which are marketing automation agents running
> inside XPoster at runtime.

---

## Node Types

The graph distinguishes four node types, annotated in `docs/agent-graph/NOTICE.md`:

| Type | Source paths | Content |
|---|---|---|
| **Source Code** | `src/`, `tests/` | C# implementation logic, domain models, services, test coverage |
| **Documentation** | `docs/` (excl. `docs/agent-graph/`) | Natural language only — architecture intent, setup guides, ADRs |
| **Infrastructure** | `infra/` | Bicep / ARM / YAML — cloud resources and deployment topology |
| **Generated** | `docs/agent-graph/` | Auto-generated by `persist-agent-graph.yml` on every push to `develop`. Do not use as source of truth for code or docs content. |

---

## Output Formats

Each graph generation run produces three files under `docs/agent-graph/backend/`:

| File | Format | Best used for |
|---|---|---|
| `wiki.md` | Markdown wiki | Human reading, PR review |
| `report.md` | Structured report | LLM prompt injection |
| `graph.json` | JSON | Programmatic agent consumption |

---

## How It Works

Graph persistence is handled by **`persist-agent-graph.yml`**, which runs on every
push to `develop` (i.e. after each merged PR).

```
Push to develop
    │
    └─► persist-agent-graph.yml
            Install .NET 10 SDK
            dotnet tool install --global graphify-dotnet  (in /tmp)
            graphify run . --format wiki,report,json
            output → docs/agent-graph/backend/
                │
                └─► git commit "docs(graph): regenerate agent graph [skip ci]"
                    push directly to develop via BOT_PAT
```

### Key implementation details

- **`/tmp` install**: `graphify-dotnet` requires .NET 10. Installing the tool
  outside the repo directory bypasses `global.json` (which pins the SDK to 8.0.x)
  and allows the .NET 10 SDK to be used.
- **`BOT_PAT`**: `develop` is a protected branch. `GITHUB_TOKEN` is rejected with
  403 when pushing directly. `BOT_PAT` is a fine-grained Personal Access Token
  (scope: `Contents: Read & Write`) stored as a repository secret, which
  authenticates as an authorized actor and bypasses branch protection.
- **`[skip ci]`** in the commit message prevents `ci.yml` from re-triggering on
  the bot commit, closing the CI loop.
- **`paths-ignore: docs/agent-graph/**`** in the workflow trigger ensures the bot
  commit itself does not re-fire the workflow.

## Using the Graph with AI Coding Assistants

The recommended workflow for AI-assisted development on XPoster:

1. **Load `docs/agent-graph/backend/report.md`** into your AI assistant context
   at the start of a session. This gives the agent a full structural map of the
   codebase — components, dependencies, and relationships — without reading
   every source file.
2. **Reference specific nodes** from `wiki.md` when asking the agent to work on
   a specific component (e.g. `ISender`, `OrchestratorFactory`, `AiServiceFactory`).
3. **Use `graph.json`** for programmatic workflows — for example, a script that
   finds all classes implementing `ISender` before scaffolding a new sender plugin.

### Example prompt

```
Context: see docs/agent-graph/backend/report.md

Task: add a new ISender implementation for Bluesky.
Follow the same pattern as XSender and InSender.
Register it in Program.cs and add a ScheduledOrchestrationProfile entry.
```

## How to Trigger Manually

The `persist-agent-graph.yml` workflow can be triggered manually via `workflow_dispatch`:

1. Go to **Actions** → **Persist Agent Graph** in the GitHub UI.
2. Click **Run workflow** → select the branch → **Run workflow**.

Or via CLI:

```bash
gh workflow run persist-agent-graph.yml --ref develop
```

## How to Extend

| Goal | What to change |
|---|---|
| Add a new output format | Add the format name to `--format wiki,report,json,...` in the workflow step |
| Change the output directory | Update `--output` in the backend step |
| Analyse only a subfolder | Replace `.` with the relative path (e.g. `src/`) in the `graphify run` command |
| Pin the graphify-dotnet version | Use `dotnet tool install --global graphify-dotnet --version X.Y.Z` |
